O que é um componente de software [1]

O termo tem significado variável na literatura, e o capítulo reconhece que isso causa confusão. Por isso estabelece uma definição de trabalho.

A definição de trabalho

Componente de software é a parte de uma aplicação responsável pela execução de determinada tarefa ou serviço. Exemplo do capítulo: verificar se um CPF informado num sistema de vendas é válido.

Como ele se posiciona

Pode conter uma ou várias classes. Recebe informação, devolve resultado. É mais complexo e mais independente que um framework, porém menos flexível; pode ser reutilizado se acoplável sem alterar a aplicação existente.

06 O que é um componente
5

A regra de independência, a mais importante do ciclo [1]

Exemplo do capítulo: a máquina de cartão precisa consultar a operadora para confirmar o pagamento.

A regra

Se o sistema da operadora tiver problema, a máquina não pode ficar esperando indefinidamente. Um componente de software deve ser capaz de executar sua tarefa sem depender do resultado de outros componentes, e, sem resposta, deve parar e ficar pronto para um novo uso.

Na Rota Sul

O equivalente é a integração com o parceiro da última milha: se o parceiro não responde, a expedição não pode travar. O capítulo observa que isso nem sempre acontece com o uso de frameworks.

Por que a indústria adotou componentes [1]

Nos últimos 30 ou 40 anos, a narrativa do capítulo sai do monolítico até chegar aos componentes.

Monolítico
interface para ler e gravar
→
PCs em paralelo

→
Servidores interligados
filiais, fornecedores, web
→
Duas camadas travadas
difícil alterar, difícil reusar
→
Componentes
flexível, fácil integrar
O bônus que puxa o Ciclo 2

Componentes podem ser adaptados a vários modelos de arquitetura, e isso levou alguns desenvolvedores a agrupar componentes de funções semelhantes dentro de camadas de serviço.

MVC, as três camadas [1]

Um dos primeiros padrões de projeto a surgir, anterior aos próprios componentes de software. Orienta o desenvolvedor a organizar seus componentes em três camadas.

Modelo

Regras de negócio, gerenciamento da conexão com bases de dados, e a lógica que mantém o software em execução.

Visão

Permite ao usuário informar dados ou ter acesso aos dados que o sistema movimenta.

Controle

Controla a troca de informações entre os componentes das outras duas camadas.

A interação entre elas

Controle envia comandos para Visão atualizar a tela ou para Modelo atualizar o estado; Modelo notifica Visão e Controle das mudanças; Visão requisita a Controle e Modelo as atualizações a mostrar.

A evolução para 3 e N camadas [1]

O MVC surgiu na década de 1970 para um cenário específico, e vem sendo aperfeiçoado desde então.

O que forçou a mudança

O usuário móvel: num primeiro momento seria só um componente da camada Visão, mas o aplicativo tem seu próprio modelo de arquitetura, adaptado à linguagem e ao ambiente em que roda.

O que se redistribuiu

Os componentes da camada Modelo precisaram virar subcamadas: camada de rede, camada de dados, e assim por diante, cada uma nomeada pelo que faz.

Daí os termos do título de hoje

Como a camada Modelo passou a fazer muita coisa, ficou mais simples nomear as subcamadas pelo que fazem: arquitetura em 3 camadas, arquitetura em N camadas.

Laboratório, passo 4: a implementação em memória

Ainda em pedido/repository, criar PedidoRepositoryEmMemoria, guardando os pedidos numa lista e gerando o id com um contador.

@Repository
public class PedidoRepositoryEmMemoria implements PedidoRepository {
  private final List<Pedido> pedidos = new ArrayList<>();
  private final AtomicLong contador = new AtomicLong(0);

  public Pedido salvar(Pedido pedido) {
    pedido.setId(contador.incrementAndGet());
    pedidos.add(pedido);
    return pedido;
  }

  public List<Pedido> listarTodos() {
    return Collections.unmodifiableList(pedidos);
  }
}

Laboratório, passo 6: escrever o serviço

Em pedido/service, criar PedidoService, recebendo PedidoRepository pelo construtor. A regra mínima obrigatória: pedido sem cliente informado é recusado.

@Service
public class PedidoService {
  private final PedidoRepository pedidoRepository;
  public PedidoService(PedidoRepository pedidoRepository) {
    this.pedidoRepository = pedidoRepository;
  }
  public Pedido registrar(Pedido pedido) {
    if (pedido.getCliente() == null || pedido.getCliente().isBlank()) {
      throw new IllegalArgumentException("Pedido sem cliente informado é recusado.");
    }
    return pedidoRepository.salvar(pedido);
  }
  public List<Pedido> listar() {
    return pedidoRepository.listarTodos();
  }
}

Laboratório, passo 7: escrever o controlador

Em pedido/web, criar PedidoController, mapeada em /pedidos. Qualquer if de negócio aqui reprova o critério de aceitação do dia.

@RestController
@RequestMapping("/pedidos")
public class PedidoController {
  private final PedidoService pedidoService;
  public PedidoController(PedidoService pedidoService) {
    this.pedidoService = pedidoService;
  }
  @GetMapping
  public List<Pedido> listar() {
    return pedidoService.listar();
  }
  @PostMapping
  @ResponseStatus(HttpStatus.CREATED)
  public Pedido registrar(@RequestBody Pedido pedido) {
    return pedidoService.registrar(pedido);
  }
}
