Por que persistir com um mecanismo eficiente [1]

O objetivo principal de um aplicativo é prover dados a seus usuários, obtidos de outros sistemas ou digitados pelo próprio usuário; para isso, ele precisa persistir esses dados com eficiência, mantendo-os sempre disponíveis e atualizados.

A forma mais comum de armazenamento é um SGBD, sistema de gerenciamento de banco de dados. O capítulo cita uma proporção de mercado de aproximadamente 80% de SGBDs relacionais, que executam SQL, contra 20% para os demais modelos, incluindo NoSQL.

A origem do ODBC

Entre 1970 e 1990, os aplicativos evoluíram até um padrão chamado ODBC, Open DataBase Connectivity, a primeira solução a manter alguma independência entre o aplicativo e o SGBD que ele usa.

Framework contra API de persistência, a distinção do capítulo [1]

Uma camada de persistência independente da aplicação pode ser distribuída como componentes de software: na forma de um framework, ou na forma de uma API.

Framework

Os componentes têm interfaces de conexão que acoplam o framework ao aplicativo; é o framework quem determina como a camada de persistência funciona, ainda que o desenvolvedor mantenha algum controle.

API

Os componentes também têm interfaces de conexão, mas quem realiza as tarefas de persistir é a própria API, sem o desenvolvedor controlar como isso acontece por dentro.

PedidoRepositoryJdbc não é nenhum dos dois

É o próprio desenvolvedor controlando cada instrução SQL, sem framework nem API de persistência no meio. É exatamente esse contraste, sentido na mão, que prepara a Aula 15.

Exercício individual: Spring Data JPA é framework ou API?

Cinco minutos, por escrito, aplicando a distinção do capítulo entre framework e API de persistência.

Responder

  1. Segundo o capítulo, framework é quem determina como a camada de dados funciona, com algum controle do desenvolvedor; API é quem executa as tarefas de persistir sem esse controle.
  2. Classificar: Spring Data JPA, que a Aula 15 vai apresentar, é mais parecido com framework ou com API?

Gabarito. Mais parecido com framework, porque o desenvolvedor escreve a interface do repositório e mantém controle sobre o mapeamento das entidades, mesmo que o Spring Data gere a implementação.

Mapa objeto-relacional, a raiz do problema [1]

A estrutura de tabelas de um SGBD relacional não é diretamente mapeável para a forma como a orientação a objetos estrutura classes e objetos.

Um ORM orienta o desenvolvedor a escrever classes de entidade, cada uma representando uma entidade do SGBD, informando à API o nome da entidade, as colunas e as restrições de chave. A API usa reflexão de objetos para elaborar os comandos SQL a partir dessas classes.

O capítulo já mostra o próximo passo

Uma classe Banda anotada @Entity, @Table, @Id, e uma fachada chamando EntityManager. Isso é JPA, o assunto da Aula 15: nenhuma dessas anotações entra no laboratório de hoje.

Os cinco padrões de projeto para persistência [1]

O capítulo lista cinco padrões usados no desenvolvimento de frameworks e APIs de persistência.

Unit-of-Work

Agrupa várias instruções SQL numa única transação.

Repository

Camada abstrata de dados, usada em vez de conectar direto à base.

Bridge

Conecta um aplicativo a diferentes tipos de base de dados.

Factory

Modo conveniente de criar os objetos que a regra de negócio precisa.

Gateway

Lógica de conexão entre regra de negócio e banco de dados.

O nome que faltava desde a Aula 06

PedidoRepository é uma aplicação do Repository Pattern: a turma usa esse padrão há oito aulas sem o nome.

Exercício em duplas: ainda seria Repository Pattern?

Cinco minutos, em duplas. Reler a definição de Repository Pattern do capítulo.

Decidir

  1. Se PedidoService chamasse DriverManager.getConnection(...) diretamente, dentro de si mesmo, em vez de depender de PedidoRepository, isso ainda seria uma aplicação do Repository Pattern?

Gabarito. Não, porque o padrão exige exatamente a camada abstrata entre a aplicação e a base, e uma conexão direta dentro do serviço apaga essa camada, mesmo que o resultado funcione.

Quiz de fixação

A Rota Sul usa a interface PedidoRepository, com implementações trocáveis, sem que PedidoService mude uma linha. Qual padrão do capítulo descreve essa prática?
  • A Unit-of-Work, agrupa várias instruções SQL numa única transação.
  • B Repository, camada abstrata de dados em vez de conectar direto à base.
  • C Bridge, conecta um aplicativo a diferentes tipos de base de dados.
  • D Gateway, liga a regra de negócio ao banco de dados.

Laboratório, passo 2: subir um MySQL local

while (resultado.next()) {

Laboratório, passo 7: desativar a implementação em memória
